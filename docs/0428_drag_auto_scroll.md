# 分类树拖拽自动滚动功能需求文档

## 1. 问题描述

在排序模式（编辑模式）和重组模式下，用户可以通过拖拽对分类树中的节点进行排序或重组。当前存在的问题是：

- 当分类列表较长，需要拖拽的目标节点位于当前视口之外时，用户**无法直接将项目拖入视口外的区域**。
- 鼠标一旦离开当前视口范围，列表不会自动滚动，导致操作受限。

## 2. 解决方案

在拖拽过程中（`dragMoveEvent`），实时检测鼠标指针在视口中的相对位置：

| 鼠标位置 | 行为 |
|---------|------|
| 视口顶部 20% 区域 | 列表**持续向上滚动** |
| 视口底部 20% 区域 | 列表**持续向下滚动** |
| 视口中间 60% 区域 | 停止自动滚动，正常拖拽 |

### 2.1 交互细节

- **滚动触发阈值**：以视口高度（`viewport().height()`）为基准，顶部 20% 和底部 20% 为触发区域。
- **滚动速度**：每 50ms 滚动固定像素（如 15~20px），确保流畅但不过快。
- **滚动方向**：
  - 向上滚动 → `verticalScrollBar().setValue(current - step)`
  - 向下滚动 → `verticalScrollBar().setValue(current + step)`
- **边界保护**：滚动值不超过 `minimum()` 和 `maximum()` 范围。
- **停止条件**：
  - 鼠标移回中间 60% 区域时停止自动滚动。
  - 释放鼠标（`dropEvent`）时停止自动滚动。
  - 拖拽离开控件（`dragLeaveEvent`）时停止自动滚动。

### 2.2 技术实现要点

- 在 `CategoryTreeWidget.__init__` 中创建一个 `QTimer` 实例（如 `_auto_scroll_timer`），用于驱动持续滚动。
- 在 `dragMoveEvent` 中根据鼠标 Y 坐标判断区域，启动/停止 timer 并设置滚动方向。
- timer 的 `timeout` 信号连接到滚动逻辑，每次触发时移动 `verticalScrollBar()` 的值。
- 在 `dropEvent` 和 `dragLeaveEvent` 中确保调用 timer 的 `stop()` 方法，防止拖拽结束后仍继续滚动。
- 自动滚动过程中应继续调用 `super().dragMoveEvent(event)` 或保持 Qt 的 drop indicator 正常显示，确保用户能看到插入位置。

## 3. 影响范围

- **文件**：`ui/main_window.py`
- **类**：`CategoryTreeWidget`
- **涉及方法**：
  - `__init__` — 新增 timer 初始化
  - `dragMoveEvent` — 新增自动滚动检测逻辑
  - `dropEvent` — 确保停止 timer
  - 新增 `dragLeaveEvent` — 确保停止 timer

## 4. 验收标准

- [ ] 在排序模式下，拖拽一个分类节点到视口顶部 20% 区域时，列表自动向上滚动。
- [ ] 拖拽到视口底部 20% 区域时，列表自动向下滚动。
- [ ] 鼠标移回中间区域时，自动滚动立即停止。
- [ ] 释放鼠标完成 drop 后，自动滚动立即停止。
- [ ] 拖拽离开分类树控件后，自动滚动立即停止。
- [ ] 不影响现有拖拽排序和重组的逻辑与规则限制。
- [ ] 代码通过安全审查，无异常循环、资源泄漏或越界访问风险。
