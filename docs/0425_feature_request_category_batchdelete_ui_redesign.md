# 功能需求文档：类别管理 + 批量删除 + UI 重设计

> 文档编号：0425-REQ-001  
> 创建日期：2026-04-25  
> 状态：待开发  

---

## 一、需求背景

当前密码保险箱主界面存在以下体验问题：

1. **类别管理缺失**：AI 一键整理后会生成新分类（如"开发工具"、"生活技能"），但用户无法对这些分类进行重命名或删除，左侧导航栏只能被动接受。
2. **删除操作低效**：目前删除账号必须逐个点开详情页 → 点击删除 → 确认，102 条账号需要重复 102 次操作。
3. **列表界面空间利用率低**：单条条目高度 70px，中间大量留白，分组字母标题占用额外空间，整体信息密度远低于主流密码管理器（Apple Passwords、1Password）。

---

## 二、功能需求

### 2.1 类别管理（右键菜单）

**交互方式**：在左侧分类导航栏（`category_list`）的任意分类项上右键点击，弹出上下文菜单。

**菜单选项**：
- `📝 重命名类别` — 弹出输入框，输入新名称后确认
- `🗑️ 删除类别` — 弹出确认对话框

**重命名逻辑**：
1. 弹出 `QInputDialog`，预填充当前分类名
2. 用户输入新名称，点击确认
3. 调用 `DatabaseManager.update_category_name(old, new)` 或逐条 UPDATE
4. 更新内存缓存 `_cached_accounts`，刷新列表和导航
5. 当前选中的分类如果正好是被重命名的，需要更新 `current_category`

**删除逻辑**：
1. 弹出 `QMessageBox` 确认："删除分类 [XXX]？该分类下的 N 个条目将移至"其他"。"
2. 点击确认后，执行 SQL：`UPDATE accounts SET category = '其他' WHERE category = ?`
3. 刷新左侧导航栏（调用 `_reload_categories()`）
4. 刷新列表（调用 `load_accounts()`）
5. **禁止删除"全部"分类**（菜单中禁用或隐藏）

**数据库层需求**：
- `DatabaseManager` 新增 `rename_category(old_name: str, new_name: str) -> int`（返回影响的行数）
- `DatabaseManager` 新增 `delete_category(category_name: str) -> int`
- `URLDatabaseManager` 同理新增对应方法

**Service 层需求**：
- `AccountService` 新增 `rename_category()`, `delete_category()`
- `URLService` 新增 `rename_category()`, `delete_category()`

### 2.2 批量删除条目

**交互方式**：在底部工具栏新增一个 `批量删除` 按钮。点击后进入"选择模式"。

**界面状态机**：

```
正常模式 ──[点击"批量删除"]──→ 选择模式
                                    │
                                    ├─ 用户勾选条目（复选框）
                                    ├─ 点击"全选" → 勾选当前视图所有条目
                                    ├─ 点击"取消" → 返回正常模式
                                    └─ 点击"删除(N)" → 确认对话框 → 删除 → 返回正常模式
```

**选择模式 UI 变化**：
1. 列表中每个条目的左侧出现复选框（`QCheckBox`）
2. 底部按钮区替换为：
   - 左侧：`取消` 按钮（退出选择模式）
   - 中间：`全选` / `取消全选` 切换按钮
   - 右侧：`删除 (N)` 按钮（红色，N 为已选数量）
3. 顶部标题区显示 `"已选择 N 项"`

**删除逻辑**：
1. 点击 `删除(N)` 后弹出确认对话框："确定删除已选中的 N 个条目？删除后将移至回收站。"
2. 调用 `account_service.soft_delete_account(id)` 逐条删除（已有方法）
3. 删除完成后退出选择模式，刷新列表
4. 显示 `QMessageBox.information` 提示删除成功

**技术实现要点**：
- 使用一个状态变量 `self._selection_mode = False` 控制
- 复选框可以放在 `AccountListItem` 内部，通过 `set_selection_mode(bool)` 方法控制显示/隐藏
- 选中状态存储在字典中：`self._selected_items = {account_id: True/False}`
- 需要考虑：选择模式下点击条目不应打开详情页，而是切换复选框状态

### 2.3 列表 UI 重设计

#### 2.3.1 设计参考（Apple Passwords / 1Password / Apple HIG）

通过调研 Apple Passwords（iOS 18）、1Password 及 Apple Human Interface Guidelines，总结当前主流密码管理器的列表设计规范：

| 设计要素 | Apple Passwords | 1Password | 当前实现 | 改进方向 |
|---------|----------------|-----------|---------|---------|
| **单条高度** | ~56-60pt | ~56pt | 70px | 降至 56-60px |
| **图标** | 左侧 40x40 圆角图标/首字母 | 左侧 36x36 图标 | 无图标 | 增加首字母圆形图标 |
| **主标题** | 网站/应用名（16pt Semibold） | 条目名（16pt Medium） | 应用名（左对齐） | 居中偏左，加粗 |
| **副标题** | 用户名（13pt Gray） | 用户名/邮箱（13pt Gray） | 邮箱/用户名（第二行） | 主标题下方一行，灰色小字 |
| **右侧信息** | 分类标签 / 箭头 | 分类标签 / 箭头 | 分类文字（右侧） | 改为 Pill 形状小标签 + 右箭头 |
| **分组方式** | 按分类分组，字母索引导航 | 按分类/字母分组 | 按首字母分组（A-Z） | **移除字母分组**，改为紧凑列表 |
| **分割线** | 细线 0.5pt，浅灰 | 细线 | 无 / 大间距 | 添加细分割线 |
| **信息密度** | 高，每屏 10-12 条 | 高 | 低，每屏 6-7 条 | **每屏 10-12 条** |

#### 2.3.2 具体设计方案

**A. 列表项（AccountListItem）重新设计**

```
┌─────────────────────────────────────────────────────────────┐
│ [✓] [圆] 应用名称              [分类标签]  > │   ← 高度 56px
│      用户名/邮箱（灰色小字）                                 │
├─────────────────────────────────────────────────────────────┤
│ [ ] [圆] GitHub                [开发工具]  > │
│      leo****n89                                              │
├─────────────────────────────────────────────────────────────┤
│ [ ] [圆] Google (Gmail)        [个人身份]  > │
│      leo****uan                                              │
└─────────────────────────────────────────────────────────────┘
```

- **复选框**：选择模式下显示在左侧（宽 24px），正常模式隐藏
- **图标区域**：40x40 圆形背景，颜色根据应用名哈希生成，显示应用名首字母（如"G" for Google）
- **主标题**：`app_name`，`font-size: 15px`，`font-weight: 600`，颜色 `#1a1a1a`
- **副标题**：`username`，`font-size: 12px`，颜色 `#888888`
- **右侧**：
  - 分类标签：圆角矩形背景（`border-radius: 10px`，`padding: 2px 8px`），文字 `11px`，颜色与背景形成对比
  - 右箭头：`>` 或 `›`，颜色 `#ccc`
- **分割线**：底部 1px 实线 `#f0f0f0`

**B. 移除字母分组标题**

当前实现按首字母 A-Z 分组，每组前有字母标题（如"A"、"B"）。这种设计在条目数量多时会浪费大量空间。

- **移除** `grouped = {}` 的字母分组逻辑
- 改为**扁平列表**，直接按 `app_name` 排序后显示
- 保持按字母排序（A-Z），但不显示分组标题
- 类似 Apple Passwords 的连续列表风格

**C. 左侧分类导航优化**

```
┌─────────────┐
│ 分类         │
├─────────────┤
│ 全部 (102)  │  ← 显示数量
│ 个人身份 (5) │
│ 其他 (12)   │
│ 学业学习 (8) │
│ 工作 (15)   │
│ ...         │
└─────────────┘
```

- 每个分类后显示该分类下的条目数量
- 字体略微缩小（13px），行高 36px（更紧凑）
- 当前选中项使用蓝色背景 + 白色文字（保持现有）

**D. 整体布局微调**

- 列表区域的内边距：`padding: 8px 12px`（左右留出适当边距）
- 条目之间的间距：由分割线取代（不再使用 8px 间距）
- 底部工具栏：按钮更紧凑，减少 `padding`

#### 2.3.3 颜色方案（保持现有主题兼容性）

```css
/* 主标题 */

/* 分类标签 */

font-size: 11px;
border-radius: 10px;

/* 圆形图标背景 */

color: white;
font-size: 16px;
font-weight: bold;
border-radius: 50%;
```

## 四、风险与注意事项

1. **分类导航数量过多时的滚动**：AI 可能生成 10+ 分类，左侧导航需要支持滚动，保持现有 `QListWidget` 即可。
2. **批量删除性能**：102 条账号逐条执行 `soft_delete_account` 应该很快（SQLite 本地），但如果数量达到数千条，需要考虑事务批量处理。
3. **URL 库与账号库的一致性**：所有类别管理、批量删除、UI 改造需要同时支持 `accounts` 和 `urls` 两个库。
4. **复选框与现有点击事件的冲突**：选择模式下，点击条目应切换复选框而不是打开详情。需要重写 `itemClicked` 事件处理。
5. **图标颜色一致性**：首字母圆形背景的颜色应根据应用名稳定生成（相同的应用名永远产生相同的颜色），可使用简单的哈希算法。
